# Start with the smallest useful module

Every repository is independently usable. The [module guide](modules.md) gives prerequisites,
commands and expected outputs. These first examples need no provider credential, model call
or external writer.

| You want to… | Start with… | First useful result |
| --- | --- | --- |
| Give an agent a clear coding process | Factory | Checked scaffold and phase-one practices |
| Clarify agent access and execution boundaries | OPS | Security-control contract and verified upstream source snapshot |
| Assess deterministic authority | CROA | An evidence packet to complete with current facts |
| Understand cost and intervention-free quality | Observability | Recomputed synthetic cost/quality comparison |
| Design an integrated software factory | SpaceShip | Catalog checks, then the architecture roadmap |

## Combine contracts when needed

For a team using Factory, OPS can define runtime boundaries, CROA can assess evidence and
Observability can measure verified task outcomes. SpaceShip specifies their deterministic
coordination. These relationships do not make repositories installation dependencies.

Read the [integration contract](../knowledge/operations/module-integration.md) before writing
adapters. Keep source, policy, artifact, check and usage identities joined with provenance.
Passing documentation/example checks cannot establish sandbox or deployment safety.

## Build the integrated path progressively

Follow [PLAN.md](../PLAN.md) and the [implementation gates](../knowledge/operations/implementation-and-poc.md).
Start with the reuse spike and offline ParcelDesk mission. Provider, GitHub, identity and target
paths each need their own scopes and qualification. A request example does not imply universal
harness compatibility.
